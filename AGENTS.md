# Project instructions

This project is Mealie JSON Create, a Windows PowerShell WPF recipe-to-Mealie JSON application.

## Documentation and completion checks

- Review README.md for every change and update affected behaviour, setup, examples, limitations and validation instructions in the same change. Keep it accurate for the current source; clearly label planned features as unimplemented.
- Before completing work, check README.md, CHANGELOG.md and version references for consistency. Run relevant checks and report their results and any outstanding limitations.

## Recipe classification

- Categories must come from the controlled list in Recipe.Classification.json. Keep labels and definitions there as the single source for the prompt, schema and validation; update RECIPE-CLASSIFICATION.md when changing them.
- Tags must come from an explicitly defined list; Ollama selects applicable entries rather than inventing new tags.
- Required tools may be generated by Ollama from the recipe's method and equipment requirements.
- Keep future ideas and outstanding feature decisions in FUTURE-DEVELOPMENTS.md; move completed behaviour into README.md and CHANGELOG.md.
- Do not force arbitrary categories, tags or tools merely to populate a field. The initial category/tag lists are approved. Agree tool inclusion rules before implementing required tools.

## Versions and release notes

- Maintain CHANGELOG.md whenever making a user-visible change. Add concise notes under Unreleased while work is in progress.
- Assess the version impact of each user-visible change using the README.md policy. Keep work under Unreleased until a release is requested; do not silently rebuild or replace an existing published version.
- For a new local release, choose a version using the README.md policy, update AppVersion in Recipe.Core.ps1, and move the completed Unreleased notes into a dated section for that version. Leave an Unreleased heading for future work.
- Never overwrite the contents of an already published release; publish a new version instead. Correct factual documentation errors transparently.
- Keep the app footer, build metadata, changelog heading and EXE filename consistent with AppVersion. Do not introduce a second version constant.
- All built EXEs must include the version in the filename: MealieJsonCreate-MAJOR.MINOR.PATCH.exe. Keep build outputs in dist/ and out of Git; distribute EXEs through GitHub Releases.
- Keep Windows PowerShell 5.1 compatibility unless a required feature justifies changing it.
